

# BuildTrack - Project Overview for Team Members

## What is the problem?

Before we start building the app, it's important to understand **why this project exists**.

Most small and medium construction companies still manage their work using traditional methods like notebooks, WhatsApp chats, phone calls, and Excel sheets. There is usually no single place where all project information is stored.

Let's take an example of a normal working day.

A site engineer reaches the construction site in the morning and supervises the workers. Throughout the day, they need to keep track of many things:

* What work was completed today
* Which workers came to the site
* How much construction material was used
* Whether any problems or defects were found
* Photos of the work completed

At the end of the day, the project manager asks for a daily report. Since all the information is scattered in different places, the engineer has to collect everything manually.

For example:

* Progress is written in a notebook.
* Photos are stored in the phone gallery.
* Attendance is maintained on paper.
* Material usage is written somewhere else.
* Updates are shared through WhatsApp.

This creates several problems.

### Problems faced

* Too much paperwork.
* Information gets lost easily.
* Daily reports take a long time to prepare.
* Photos become difficult to organize.
* Managers cannot see real-time project progress.
* Issues or defects are often forgotten.
* Finding old records later is very difficult.

Instead of focusing on construction work, engineers spend a significant amount of time preparing reports.

---

# Our Solution

To solve these problems, we will build a Flutter mobile application called **BuildTrack**.

The idea is simple.

Instead of maintaining multiple notebooks and sending information through WhatsApp, the engineer will record everything directly inside the app.

Whenever work is completed, they simply open the app, select the project, enter today's progress, upload photos, record attendance, and submit the report.

All information is stored in one place and can later be viewed by the project manager.

This saves time and keeps every project organized.

---

# How the App Will Work

The daily workflow will look something like this:

1. Engineer logs into the app.
2. Selects the construction project.
3. Records today's work.
4. Uploads site photos.
5. Marks worker attendance.
6. Records material usage.
7. Reports any issues or defects.
8. Submits the daily report.

The manager can then open the application and see the latest updates without calling the engineer every evening.

# Features We Will Build

## Phase 1 (MVP)

These are the features required for the first working version.

* User Login
* Project List
* Daily Progress Report
* Upload Construction Photos
* Worker Attendance
* Material Usage Record
* Issue / Defect Reporting
* Daily Report Summary

These features are enough to solve the core problem of replacing paper records.

# How We Plan to Build It

We are **not** trying to build every feature at once.

Our plan is to divide the project into small parts.

### Step 1

Design the screens and understand the user flow.

### Step 2

Create user login and project management.

### Step 3

Build the daily reporting system.

### Step 4

Add attendance, materials, and photo uploads.

### Step 5

Add issue reporting.

### Step 6

Building the app step by step will make it easier for everyone to contribute.

# How Will We Know the Project Is Successful?

Our project can be considered successful if:

* Engineers can create daily reports much faster than using paper.
* Managers can easily check project progress.

If the app makes the daily reporting process easier and saves time, then we have achieved our goal.

# Simple Glossary

**Flutter:** A framework used to build mobile applications for Android and iPhone from a single codebase.

**MVP (Minimum Viable Product):** The first version of the app that includes only the essential features.

**UI (User Interface):** The screens and buttons that users interact with.

**Backend:** The part of the application that stores and manages data behind the scenes.

**Database:** A place where all project information is saved.

**Offline Mode:** Allows the app to continue working even when there is no internet connection.

**Daily Report:** A summary of everything that happened at the construction site during the day.

**Defect:** Any problem or issue found during construction that needs to be fixed.
